# week06：序列窗口与预测基线

使用 ETTh1 的前 14,400 条小时记录，以过去 24 小时的 `OT` 预测下一小时 `OT`。数据来自 [ETDataset 官方仓库](https://github.com/zhouhaoyi/ETDataset)，原文件共 17,420 行，实验范围为 2016-07-01 00:00 至 2018-02-20 23:00。

## 环境与运行

- Python 3.12.14
- NumPy 2.5.4、pandas 3.1.0、Matplotlib 3.11.2、scikit-learn 1.9.1

```bash
python run_windows.py
python run_baselines.py
```

两个入口只负责配置、遍历实验和组装记录。`data.py` 读取、检查、构造和划分数据；`models.py` 训练与预测；`evaluation.py` 计算及复核指标；`reporting.py` 保存表格和绘图。更具体的调用关系见 [代码讲解.md](代码讲解.md)。

## 固定设置与时间划分

- 窗口长度 24，预测步长 1，只使用历史 `OT`。
- 训练目标：2016-07-02 00:00 至 2017-06-25 23:00，共 8,616 条。
- 验证目标：2017-06-26 00:00 至 2017-10-23 23:00，共 2,880 条。
- 测试目标：2017-10-24 00:00 至 2018-02-20 23:00，共 2,880 条。
- 窗口先从完整序列构造，再按目标时刻划分。因此首条验证样本可使用验证起点之前的 24 小时，首条测试样本也可使用测试起点之前的 24 小时。逐时单步预测中，预测 10 月 24 日 01:00 时可以使用当天 00:00 的真实观测；一次性预测未来 120 天则不能使用这些尚未出现的真实值。
- 标准化器和回归模型只在训练集拟合。验证集用于选配置，测试集不参与选择。

## 窗口构造检查

前 12 小时的 `OT` 总体从 30.531 下降到 20.119，中间也有回升，例如 06:00 的 22.792 上升到 07:00 的 23.144。

窗口长度 3 得到 9 条样本，`X` 形状为 `(9, 3)`；首条用 00:00–02:00 的 `[30.531, 27.787, 27.787]` 预测 03:00 的 25.044。窗口长度 5 得到 7 条样本，`X` 形状为 `(7, 5)`；首条用 00:00–04:00 预测 05:00。两组最后一个目标都是 11:00。一般地，长度为 `N` 的序列使用长度 `L` 的窗口时，样本数为 `N-L`，目标下标为 `L` 到 `N-1`，每个输入的最后观测都比目标早 1 小时。

`window_examples.csv` 的一行是一条样本。`input_start` 和 `input_end` 是原序列下标，`target_index` 紧随窗口之后，`target_time` 和 `target_value` 来自原 CSV，`input_values` 来自 `X` 的对应行。

## Ridge 路线与选择

选择 Ridge 是为了观察增强权重约束后，训练误差与验证误差怎样变化。三个正数候选为 `0.1、10、1000`，覆盖弱、中、强正则化。它们均使用“标准化 → Ridge”，每个候选独立在相同训练窗口拟合。

| 配置 | 训练 RMSE | 验证 RMSE |
| --- | ---: | ---: |
| 普通线性回归 | 1.043134 | 0.910183 |
| Ridge 0.1 | 1.043135 | **0.910179** |
| Ridge 10 | 1.045884 | 0.912002 |
| Ridge 1000 | 1.488241 | 1.218373 |

Ridge 候选中 `alpha=0.1` 的验证 RMSE 最小，因此记为 `ridge_tuned`。如果继续尝试，会在 0.1 附近增加更细的较小候选，因为它与普通线性回归非常接近，而增大到 10 已开始变差。

训练误差最低的是普通线性回归，验证误差最低的是 Ridge 0.1，二者不一致但差异只有约 0.000004。增大 `alpha` 后训练、验证误差一同升高，`alpha=1000` 出现明显欠拟合；没有“训练继续改善但验证恶化”的明显过拟合迹象。验证 RMSE 全部低于训练 RMSE，说明时段难度或季节、工况差异也会影响误差，当前一次时间划分不足以得出普遍结论；还应做多个滚动时间切分、残差随时间检查和不同窗口长度比较。

## 最终结果

四种方法按验证 RMSE 选择，`ridge_tuned` 以 0.910179 略优于普通线性回归的 0.910183，被标记为最终模型。其测试集 MAE 为 0.422652，RMSE 为 0.584526。`last_value`、`window_mean`、`lag_linear`、`ridge_tuned` 的训练、验证、测试结果都保存在 `metrics.csv`，逐时刻结果保存在 `predictions.csv`。

验证首日 00:00–07:00，油温由 20.963 连续下降到 18.642；同一时段 HUFL 从 10.851 降到 8.975 后回升并波动，二者没有全程同向。07:00 的真实油温为 18.642，上一时刻法预测 19.275，24 小时均值预测 20.890，Ridge 0.1 预测 19.360，三者都偏高；窗口均值受更早的较高温度拖累最大，Ridge 学到不同滞后位置的权重后更接近真实值。这与温度变化存在滞后、历史较高温度仍影响估计的认识相容，但不能仅凭 HUFL 与 OT 曲线认定因果，环境温度、其他负载通道和冷却状态都可能影响结果。

完整平均指标概括一个时段的总体误差，首周曲线显示误差发生在哪些局部变化上。图中 07:00 的点可由 `model + split + target_time` 直接定位到 `predictions.csv` 的一行。

## 结果文件

- `window_examples.csv`：两种窗口的全部短序列样本。
- `tuning.csv`：普通线性回归参照和三个 Ridge 候选。
- `metrics.csv`：四种最终方法在三个数据部分的指标。
- `predictions.csv`：每个模型、数据部分和目标时刻的真实值与预测值。
- `tuning_comparison.png`：不同配置的训练与验证 RMSE。
- `series_split.png`：14,400 小时油温、时间边界和首条样本历史。
- `validation_predictions.png`：验证首周油温预测及同时间 HUFL。

`reporting.py` 接收入口已经组装好的普通字典记录，不负责训练或重新计算指标。保存后，程序从 `predictions.csv` 对应的内存记录重算 MAE、RMSE，并检查样本数和重复键与汇总表一致。
